## Сценарий родителя

Короткое приглашение → «Хочу попробовать» → отдельное согласие на обработку заявки → имя родителя → возраст ребёнка → контакт → пожелания по времени. Заполненная заявка ожидает распределения. Тренер назначает время через CRM; бот отправляет родителю уведомление. Первое занятие бронируется во внутреннем расписании; второе согласует тренер.

Кнопки доступны на русском и украинском. `/coach` показывает контакт тренера, `/info` — сведения клуба, `/privacy` — фактическую обработку данных, `/delete` — удаление анкеты и брони из CRM. Команды `/ru` и `/uk` переключают язык. Самостоятельное бронирование родителями отключено: сначала собирается интерес, затем тренер распределяет желающих по времени. Реальное расписание и постоянные цены ещё не предоставлены.

## Помощники

- Приём — диалог и кнопки; интерес учитывается отдельно от согласия и анкеты.
- AI FAQ — Qwen3 отвечает по фактам клуба на RU/UK. При сбое используется резервный ответ.
- Уведомления — заполненная заинтересованная заявка приходит владельцу в Telegram с пометкой «Для тренера». CRM-ссылки в уведомлении нет; родитель получает отдельное подтверждение.
- Аналитика — Cloudflare Cron пересчитывает счётчики каждые 5 минут и пишет событие в журнал.
- Распределение — выбор тренера, SQL ограничивает вместимость занятия.
- Поиск — ежедневно проверяет открытые Telegram-страницы и связанные сообщества; городской каталог используется при доступности. Городские, районные чаты и объявления подходят наряду с семейными группами. До 20 страниц за проход; это не полный поиск всех групп.
- Контент — RU/UK черновики из утверждённых фактов клуба, без LLM.
- Публикации — очередь Telegram через официальный Bot API, только с зафиксированным разрешением, подтверждёнными правами и одобренным текстом. На данный момент ни одной разрешённой площадки не подключено.
- CRM продвижения — отдельные статусы разрешения, вступления, модерации поста, публикации, отклонения и удаления; источник подтверждения, история, время и ссылка на пост. Статусы браузерных действий записываются через защищённый API/UI, автоматического наблюдения Facebook нет.

Это модули бота и фоновые обработчики с журналом действий. Полностью автономный поиск всех Facebook/Telegram-групп и публикация в них не реализованы. Facebook Groups API удалён Meta; Facebook-поиск в браузере требует входа. Telegram-бот не может сам вступать в произвольные группы. Каталог ChatCrawler вернул 403 при первом запуске; Telegram-страницы доступны, используются исходные находки и ссылки между сообществами.

## Запуск и проверка

Node.js 22.16+:

```sh
npm ci
npm test
npm run db:local
npm run dev -- --port 8791
```

Для локальной работы создайте `.dev.vars` с ADMIN_TOKEN и WEBHOOK_SECRET. Не используйте локальные примеры секретов в production. Локальный dev исключает удалённый AI binding. Для изолированного тестового API включите DEMO_MODE=true в локальном конфиге; в production `/api/demo` выключен.

`.github/workflows/test.yml` запускает тесты. Автоматическое развёртывание из GitHub не подключено. Облачные команды и квоты: [DEPLOY.md](DEPLOY.md).

## Ограничения MVP

- Доставка Telegram — «как минимум один раз»: сбой после отправки до отметки в БД или параллельные отправители могут дать повторный ответ. При росте нагрузки нужна выделенная очередь/блокировка.
- Webhook использует max_connections=1; исходящая очередь повторяется каждые 5 минут, до 8 попыток.
- Анкета и история CRM в AI не передаются. Маскировка контактов в свободном вопросе не гарантирует удаления всех персональных сведений.
- Общий ADMIN_TOKEN; для нескольких тренеров нужен индивидуальный вход.
- Нет синхронизации с Google Calendar, учёта посещений, абонементов и автоматического удаления лидов по сроку. `/delete` удаляет данные из CRM, но не переписку Telegram.
- Журналы очищаются через 30 дней, старые подтверждения обновлений — через 7 дней. Отправленные payload очищаются после доставки.
