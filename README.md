# Karate Growth AI · Karate klub Budo

Telegram-помощник и CRM для родителей, интересующихся карате в Таллине.

**Клуб:** Karate klub Budo, Keldrimäe tn 9, Tallinn. Дети от 3 лет. **Первые 2 тренировки бесплатно.** Языки: русский и украинский.

## Как работает

1. Родитель видит предложение и подтверждает согласие на обработку заявки.
2. Бот спрашивает, хочет ли родитель посетить бесплатные тренировки: `/yes` или `/no`.
3. При интересе собирает имя родителя, возраст ребёнка, телефон/Telegram и пожелания по времени.
4. CRM показывает «Ожидает времени». Автоматического выбора занятия родителем нет.
5. Тренер добавляет занятия, затем назначает подходящее время из строки заявки. Вместимость проверяется в базе, уведомление ставится в очередь Telegram.

Предложение двух бесплатных тренировок не означает две автоматические брони: MVP распределяет первое занятие; второе согласует тренер. Учёт посещений и абонементов не реализован.

## Проверенный статус

Локально пройдены 6 автоматических проверок и HTTP-сценарий: украинская заявка → интерес → пожелания → ожидание распределения → назначение тренером → CRM. Панель открывается в Chrome. Отчёт `verification.json` содержит только синтетический тест.

Облачная тестовая версия проверена 31 октября 2026: https://karate-growth-ai.karate-growth-ai.workers.dev/ . Проверены HTTPS, D1, полный путь заявки и назначение тренером. Конкурентное назначение двух заявок на одно место дало одну бронь (HTTP 200 и 409). Реальные AI-ответы на русском и украинском проверены на модели Qwen3. Отчёты: cloud-verification.json, cloud-concurrency-verification.json, ai-verification.json.

Telegram пока НЕ подключён; реальная доставка боту НЕ проверена. Публичный адрес панели не открывает CRM без ADMIN_TOKEN. В базе только синтетические тестовые заявки, DEMO_MODE=true.

## Запуск

Node.js 22.16+ и npm:

```sh
npm ci
npm test
npm run db:local
npm run dev -- --port 8791
```

Создайте `.dev.vars` с локальными `ADMIN_TOKEN` и `WEBHOOK_SECRET`. Пример только для локальной проверки: `local-test-only-dev` и `local-webhook-test-only`. В production используйте разные случайные значения не короче 32 байт. Секреты не должны попадать в Git.

Панель: http://localhost:8791. Ключ администратора хранится только в памяти страницы. Локальный запуск исключает удалённый AI binding и не требует Cloudflare-входа.

## Тестовый путь родителя

`/start` → `/uk` или `/ru` → `/agree` → `/yes` → имя родителя → возраст → `+372…` или `@username` → пожелания по времени или `/skip`.

`/no` отмечает отсутствие интереса; `/yes` позволяет вернуться. `/privacy` показывает условия теста; `/delete` удаляет заявку, бронь и содержимое связанных старых исходящих сообщений.

Тестовый чат панели создаёт записи `demo:*` и не отправляет сообщения в Telegram. Назначение времени тестовой заявке также не вызывает настоящую отправку.

## Архитектура и ограничения

- Cloudflare Worker: HTTPS API, webhook Telegram, статическая панель.
- D1/SQLite: заявки, интерес, пожелания, слоты, брони, дедупликация обновлений, очередь ответов, журнал.
- SQL-триггер ограничивает вместимость. Назначение и постановка уведомления в очередь выполняются транзакцией D1 batch.
- Помощники в MVP — модули приёма, FAQ, бронирования и доставки. Это не независимые автономные фоновые AI-агенты.
- В облачной тестовой версии AI FAQ включён (Qwen3), в локальном режиме без удалённого binding используется резервный шаблон: факты клуба, до 100 попыток в день, ограничение ответа, резервный шаблон. CRM и история диалога в модель не передаются. Маскировка контактов не гарантирует удаления всех персональных данных из свободного вопроса.
- Telegram-очередь повторяется каждые 5 минут, максимум 8 попыток. Доставка — «как минимум один раз»: сбой после отправки до отметки в БД или параллельные отправители могут дать повторный ответ. Для высокой нагрузки нужна блокировка/выделенная очередь.
- Telegram webhook настраивается с `max_connections=1` для последовательной передачи диалога.
- DEMO_MODE принимает webhook только от TEST_CHAT_ID и блокирует реальные назначения другим chat ID. Тестовые записи отдельно помечены `demo:*`.
- Общий ADMIN_TOKEN защищает CRM; для нескольких тренеров нужен индивидуальный вход.
- Отправленные payload очищаются. Журналы хранятся 30 дней, старые подтверждения обновлений — 7 дней. Автоматическое удаление лидов по сроку пока не реализовано, доступна команда `/delete`.
- Реального расписания пока нет. Администратор добавляет его после согласования с клубом. Нет синхронизации с Google Calendar, отдельных уведомлений тренеру или учёта посещений.
- До приёма реальных заявок владелец должен заменить тестовый текст `/privacy` утверждёнными контактами и политикой обработки данных.
- Автопубликации отключены. Требуются права владельца и официальный API каждой площадки.
